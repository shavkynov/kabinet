Статус: предложения, не реализованные исправления. Основание — предварительное статическое чтение части исходников коммита 9c2708a465780c51e4664c9d7ea7f5a541dc962c. Приложение и тесты в рамках того аудита не запускались; большие файлы были доступны частично. Перед каждой задачей подтвердить проблему на актуальном коде.

## Критерий успеха

После установки обновления прежний проект, настройки и рабочие подключения сохраняются. В обычной работе нет новых диалогов, настроек, повторной авторизации или обязательных действий. Ошибки устраняются автоматически там, где это безопасно; невозможность сохранить данные не маскируется.

## Этап 1. Защита текста

### 1. Сохранение и переходы между проектами

Проверить renderer/app/13-save.js и renderer/app/02-screens.js: ошибка flushDoc может не останавливать переход, а enterProject сбрасывает dirty.

Предложение: передавать результат записи вызывающему коду; сохранять снимок с идентификаторами проекта и документа; не продолжать переход при неподтверждённом сохранении. По возможности автоматически повторять запись и продолжать исходное действие после успеха. Не замораживать интерфейс на время повторов.

UX: успешные сохранения и переходы остаются без диалогов. При длительном сбое показывать одно ненавязчивое состояние; если без решения автора безопасно продолжить нельзя, предложить конкретное восстановление, а не технические настройки. Не закрывать окно молча с несохранённым текстом.

Приёмка: отказ записи, правки во время записи, переключение проекта и закрытие окна не теряют текст и не направляют повтор в другой проект. После восстановления доступа сохранение завершается без повторного ввода.

### 2. Удаление при синхронизации

Проверить src/folder.js, afterLocalDelete: чтение и удаление могут завершаться ошибкой, а состояние всё равно очищается.

Предложение: при ошибке чтения отложить удаление; фиксировать его только после подтверждения. При несовпадении версии сначала надёжно сохранить конфликтную копию. Повторы — в фоне, без подтверждения каждого файла.

Приёмка: ошибка чтения исключает DELETE; ошибка DELETE сохраняет задачу для повтора; чужая правка остаётся восстановимой. Локальное письмо не блокируется.

## Этап 2. Безопасность подключений

### 3. TLS и секреты

Проверить src/webdav.js и davSecret в main.js: разрешение HTTP и fallback raw:.

Предложение: HTTPS для новых внешних подключений; системное защищённое хранилище без новых настроек. При обновлении сохранять работоспособные защищённые подключения. Старые открыто сохранённые секреты переносить в защищённое хранилище автоматически только после проверки успешной записи. Не менять сервер и не пересылать секреты на другой адрес.

Если защищённое хранилище недоступно — сессионный режим без записи секрета открытым текстом и одно понятное объяснение. Старое небезопасное HTTP-подключение нельзя незаметно отключить или объявить безопасным: подготовить отдельный совместимый сценарий перехода. Если он требует участия автора, сделать его однократным и явно описать исключение из идеала незаметного обновления. Не добавлять общий переключатель «отключить безопасность».

Приёмка: секреты не попадают в логи; штатный защищённый вход не требует повторной авторизации после обновления; ошибка миграции не уничтожает прежние данные.
