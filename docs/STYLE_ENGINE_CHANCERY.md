# `chancery` — канцеляриты (D.3)

Статус: пилот на Rust/UDPipe contract, только shadow diagnostics. Пользовательская подсветка, счётчики, настройки и навигация не подключены. Независимого корпуса и Precision/Recall нет.

## Правила

1. **`chancery.nominal-subject-cluster`** — отглагольное существительное в роли `nsubj` при сказуемом, с зависимой событийной цепочкой (`nmod`/`nmod:poss`, Gen). Требуется ≥2 событийных существительных; не одиночное слово.
2. **`chancery.light-verb-event-noun`** — лёгкий глагол (`осуществлять`, `проводить`, `принимать`, `оказывать`, `вести`, `производить`, `выполнять`, `совершать`, `давать`, `издавать`) + событийное существительное в `obj`/`obl`/`nsubj`.
3. **`chancery.passive-event-nominal`** — пассив (`Voice=Pass`/`aux:pass`) + событийное существительное в `nsubj:pass`/`nsubj`, **без** `obl:agent`.
4. **`chancery.official-preposition`** — официальная предложная формула (`в целях`, `в связи`, `в процессе`, `на основании`, `в области`, `в течение`, `в силу` и т.п.) + процессное существительное; даёт `low`.

## Признаки и ограничения

- Событийность — суффикс (`-ание/-ение/-яние/-тие/-ие/-ция`) и небольшой лексический класс; это **не** универсальный словарь ошибок.
- `требование`, `безопасность`, `документ`, `информация`, `оборудование` не считаются процессными для официальной формулы.
- Слова в прямой речи/цитатах исключаются через `speechRanges`.
- При повреждённом дереве/отсутствии обязательных `feats` — abstain.
- Не-high confidence: `medium` для структурно ясных конструкций, `low` для официальной формулы; confidence не калиброван.
- Не учитывается жанр/авторская стилизация; finding — кандидат, не приговор.

## Интеграция

`analyzeStructural(..., {chancery:true})` вызывается shadow после `style:parse`; findings доступны в `window.__styleShadow.chancery`/`chanceryCount`, ошибки — в `ruleErrors`. Старый `src/style.js` и UI не изменяются.

## Проверки

- Synthetic fixtures `test/style-engine-chancery.test.js` (positive/negative/technical/quotes/emoji/broken data).
- Existing `chain`/`which` tests проходят.
- Реальный Rust/GSD: `"Он осуществлял проверку документов."` → `"осуществлял проверку"`; `"Было принято решение."` → `"Было принято решение"`; `"В целях осуществления проверки..."` → `"В целях осуществления проверки"`; `"Он принял гостя."`, `"Дом был построен."`, `"В соответствии с требованиями безопасности..."` — без findings.
- Модель GSD в репозиторий не добавлена.
