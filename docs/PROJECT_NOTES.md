# Заметки о проекте «Кабинет»

Этот документ содержит подробности функций и текущей архитектуры. Не загружать целиком для каждой задачи — открывать нужный раздел по мере необходимости.

## Основные компоненты

- `main.js`: главное окно, меню, IPC (`handle` возвращает `{ok,data}` или `{ok:false,error}`), резервные копии, экспорт; данные приложения находятся в каталоге пользовательских данных Electron.
- `preload.js`: мост `window.kabinet`. Каждый `call('канал')` должен иметь соответствующий `handle('канал', ...)` в `main.js`.
- `src/`: логика проекта, глав, карточек, целей, поиска, резервного копирования, экспорта и текстового анализа. Файловые записи должны быть атомарными.
- `renderer/`: `index.html`, `style.css`, интерфейс и его текстовые инструменты. `renderer/app/*.js` — части одного скрипта; порядок и глобальные имена важны. `renderer/app.gen.js` и `renderer/dist/app.js` генерируются.
- Формат проекта — каталог с `project.json`, Markdown-главами и папками данных персонажей, мест, заметок, изображений, корзины и резервных копий. Не меняй формат без теста старых проектов.

## Языки интерфейса

- Исходные строки интерфейса пишутся по-русски. Переводы: `src/i18n-en.js`; логика перевода главного процесса — `src/i18n.js`, окна — `renderer/i18n.js`.
- Новую видимую строку добавляй в английский словарь. `npm run i18n` помогает найти непереведённые строки; тесты проверяют полноту.
- Составные строки формируй через `t('Строка {0}', значение)`, а не конкатенацией. Данные автора (названия глав, карточек, синопсис и т. п.) должны быть защищены от перевода через `translate="no"`, где это требуется.
- Язык хранится в пользовательских настройках; при смене языка приложение восстанавливает открытые проект и главу.

## Текстовые инструменты

- Орфография при наборе использует системную проверку Chromium.
- Пунктуация и грамматика: LanguageTool через `src/langcheck.js`; текст отправляется на сервер только по явному действию и после согласия пользователя либо используется локальный сервер. Подсветка не меняет текст автоматически; правка происходит по действию автора.
- Имена из карточек: `src/declension.js` строит падежные формы названия и «Имён в тексте» (по моделям склонения, без словаря); `src/namematch.js` собирает из них регулярку (дерево префиксов); формы приходят в окно в `cardIndex().forms` и идут в подсветку (`renderer/links.js`), счётчик «Встречается в главах» (`src/mentions.js`) и список известных слов проверки правописания. В карточке хранится только отказ `inflect: false`.
- Подсветка (`renderer/analysis.js`): к подсвеченным словам добавляется `title`; места пяти категорий (наречия, пассив, длинные, повторы, паразиты) собираются в `ranges` состояния плагина для переходов «‹ ›» (`stepIndex`) и для меню «Не отмечать здесь» (`analysisAt`). Исключения хранятся в `project.json`, поле `analysisSkip` (`src/editing.js`: `skipKey`, `cleanSkip`). Проверять без редактора можно через `test/analysis-harness.js` (заглушки tiptap и поддельный документ).
- Замечания LanguageTool (`src/langcheck.js`, `renderer/textcheck.js`): у каждого замечания есть вид (`kind`: орфография, пунктуация, грамматика, стиль, типографика, другое). Скрытые виды хранятся в файле настроек проверки (`hiddenKinds`, не в проекте) и отсеиваются в `filterIssues`; переключатели в «Настройки проверки».
- Типографика: `src/typo.js` и `renderer/typo.js` — кавычки, тире, многоточия и неразрывные пробелы. Поиск и автоссылки должны учитывать U+00A0.
- Анализ частей речи: `src/morph.js`; согласование времён: `src/tense.js`; разбор прямой речи: `src/speech.js`; стемминг: `src/stem.js`; слова-паразиты и повторы: `src/editing.js`; отображение анализа: `renderer/analysis.js`. Это эвристические алгоритмы — исправления должны сопровождаться регрессионными тестами. Эталонный корпус частей речи находится в `test/gold-pos.js`.

## Интерфейс и данные

- Главы без названия отображаются как «Глава N» (режим «Рассказы» использует соответствующую терминологию). Удаление переносит объекты в Корзину; не обходи этот механизм.
- Левая панель содержит рукопись, персонажей, места, заметки и корзину. Правая панель включает синопсис, заметки к главе и выбранную заметку. Не добавляй панели или кнопки без запроса автора.
- Настройки интерфейса находятся в localStorage и пользовательских JSON-файлах. Перед изменением ключей/структур найди все места чтения и записи.
- Синхронизация через облачные папки использует защиту от внешних изменений (`src/syncguard.js`, `src/fsutil.js`) и слежение за файлами (`src/watcher.js`). Не ослабляй защиту от перезаписи.
- Экспорт DOCX реализован в `src/docx.js` и `src/export.js`; проверяй выходные данные соответствующими тестами.

## Сборка и обновление

- `npm run build` собирает интерфейс.
- `npm run dist` собирает macOS-приложение; `npm run dist:win` — Windows-установщик. Сборки платформы требуют подходящей среды.
- `npm run release` запускает полную проверку и упаковывает архив проекта, исключая зависимости и артефакты сборки. Это операция выпуска, а не стандартный шаг после правки.
- Скрипт обновления автора: `scripts/update.sh`; не запускать без явного запроса.
