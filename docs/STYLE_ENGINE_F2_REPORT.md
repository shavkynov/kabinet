# F.2 — проверка установленного приложения и реального Tauri IPC

Ветка `feature/linguistic-style-engine`, исходный HEAD `e78bfc8e1101fb51835fd8b6e875b73e3b156053`.

## Что проверялось

Цепочка: ProseMirror → snapshot документа → Tauri IPC (`style:parse` / `style:cancel`) → Rust-парсер → контракт → адаптер → Decorations.

Проверка шла в настоящем окне Tauri (WebKitGTK под Xvfb, управление через `tauri-driver`), без mock-моста: в окне есть `window.__TAURI__.core.invoke`, а `styleParse` вызывает канал `style:parse`. Проект открывался кликом по списку недавних, глава читалась через `chapter:read`, ввод шёл клавишами в ProseMirror.

Прогонялись два бинарника: debug-сборка и **установленный** release-бинарник из собранного `.deb` (распакован в `/usr/bin/kabinet-tauri`).

## Важное ограничение

Модель UD Russian-GSD не использовалась и не добавлялась (статус `CONDITIONAL`). Успешный путь проверен на **игрушечной UDPipe-модели**, обученной на синтетическом трибанке (`e2e/make-toy-model.sh`, лежит только во временном каталоге). Это доказывает работу инфраструктуры (IPC, контракт, offsets, отмена, адаптер), но **не качество разбора реальной моделью**. Тест `real_model_*` с настоящей GSD-моделью остаётся `#[ignore]` и на ней не запускался.

Проверка самого `.deb` через `dpkg -i` не удалась: имя пакета «кабинет» не проходит валидацию dpkg (кириллица в поле `Package`). Это замечание к упаковке, не к анализатору. Поэтому пакет распакован `dpkg-deb -x`, а не установлен штатно. Запуск через ярлык/меню не проверялся. Проверка под Windows и macOS не выполнялась.

## Найденная и исправленная проблема

`align_block` пропускал пробелы функцией `char::is_whitespace`, а UDPipe не считает пробелами U+0085, U+2028, U+2029, U+000B, U+000C и оставляет их внутри формы токена. Текст вида `Он пришёл. Потом ушёл.` давал ошибку «Токен «Потом» не совпадает с исходником», и анализ всего блока отключался. Теперь начало токена ищется внутри пробельной серии, а ведущие и замыкающие пробельные символы формы в span не входят; `text` токена берётся из исходника, так что инвариант `text === source.slice(start, end)` выполняется по построению. Чужой текст по-прежнему не пропускается (fail-closed).

Новые тесты падают на старом коде и проходят на новом (проверено). Тест с реальной моделью `real_model_survives_non_space_separators` добавлен как `#[ignore]`; на игрушечной модели он проходит.

## Наблюдения без правок

- Документы описывают тень как не создающую Decorations, но коммит `00111ee` сделал новый анализатор источником стилевых Decorations. В реальном окне после включения тени подсветка меняется со старого анализатора на новый. Документацию нужно привести в соответствие.
- Включение тени из консоли (`kabinetStyleShadow.enable()`) — отладочный путь; пользовательского переключателя в интерфейсе нет.
- Одиночный сбой `cargo test --lib` (2 теста из 185) наблюдался один раз при параллельной нагрузке; имена тестов не зафиксированы, в 10 последующих прогонах (в том числе под нагрузкой) не воспроизвёлся. Причина не установлена.
- Время разбора больших абзацев на реальной модели не измерялось (игрушечная модель не показательна).

## Как повторить

```
cargo fetch --locked --manifest-path experiments/tauri-app/core/Cargo.toml
experiments/tauri-app/e2e/make-toy-model.sh /tmp/f2
cd experiments/tauri-app && npx @tauri-apps/cli@2 build --bundles deb
KABINET_E2E_TMP=/tmp/f2 KABINET_BIN=<путь к бинарнику> node e2e/real-ipc.js toymodel
```

Нужны `libwebkit2gtk-4.1-dev`, `xvfb`, `webkit2gtk-driver`, `tauri-driver` и `g++`.

## Лицензионный статус

Модель в репозиторий, runtime, Tauri resources и установщик не добавлялась: в `.deb` нет файлов `.udpipe` и каталога `style-models`, `tauri.conf.json` не содержит resources.
