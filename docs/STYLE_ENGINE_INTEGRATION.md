# Этап C: инфраструктурная интеграция парсера

Дата: 2026-11-19. Ветка: `feature/linguistic-style-engine`, база `4f384b4`. Модель в репозиторий и установщик не добавлена.

## Реализовано

### Rust-модуль

`experiments/tauri-app/core/src/style_parser.rs`:

- модель читается с диска; путь: `KABINET_STYLE_MODEL` или `resource_dir/style-models/russian-gsd-ud-2.5-191206.udpipe`;
- версия и SHA-256: `KABINET_STYLE_MODEL_VERSION`, `KABINET_STYLE_MODEL_SHA256`; по умолчанию GSD 2.5 и его хэш;
- SHA-256 проверяется до загрузки; несовпадение/отсутствие модели — явная ошибка;
- модель загружается один раз (`Mutex<Option<Arc<Mutex<Model>>>>`) и переиспользуется;
- текст разбивается на абзацы; между абзацами проверяется отмена;
- результат — contract `schemaVersion:1` с UTF-16 offsets, леммами, UPOS, feats, head/deprel, confidence;
- `parser` в результате содержит `name`, `version`, `modelVersion`, `modelSha256`.

### Выравнивание offsets

В `style_parser.rs` нет поиска «следующего вхождения» токена. Алгоритм:

1. Идём по исходнику слева направо.
2. Пропускаем только whitespace.
3. Требуем посимвольного совпадения формы токена.
4. После последнего токена допускаем только whitespace; иначе разбор отклоняется.
5. Байтовые offsets переводятся в UTF-16 через карту границ.

Тестами покрыты: кириллица, emoji (surrogate pairs), комбинируемый символ, NBSP, табуляция, повторяющиеся токены, несовпадение и остаток текста. При ошибке контракт не публикуется.

### Tauri IPC

- `style:parse` — текст + taskId; выполняется в `spawn_blocking`, не блокирует UI;
- `style:cancel` — отменяет задачу по id;
- при новом запросе предыдущая задача получает флаг отмены;
- результат содержит `taskId`, `cancelled`, `ms`, `parse`; ошибки возвращаются строкой и изолируются вызывающим слоем;
- мост: `window.kabinet.styleParse/styleCancel`.

### Теневой режим

`renderer/app/29-style-shadow.js`:

- включается только через `localStorage['kabinet.styleEngineShadow']='1'` (внутренняя настройка, без UI);
- при изменении текста с задержкой 900 мс вызывает `styleParse`;
- отменяет предыдущий запрос, игнорирует ответы устаревших taskId;
- результаты пишутся в `window.__styleShadow` только для диагностики;
- не создаёт Decorations, не меняет счётчики, настройки, навигацию;
- ошибки ловятся и не влияют на редактор;
- старый `src/style.js` продолжает обслуживать интерфейс.

### Реальный E2E в Tauri (macOS arm64)

Проверено на собранном debug-бинарнике Tauri, с временным app identifier и временным renderer-скриптом (в коммит не входят):

`Renderer → window.kabinet.styleParse → bridge → Tauri call → spawn_blocking → StyleParser → JSON → renderer`.

Фактические результаты из журнала приложения:

- первый разбор: `taskId 101`, IPC 992–1004 мс (включая холодную загрузку модели), сам разбор 2 мс, 2 предложения / 12 токенов, `offsetsOk: true`;
- повторный разбор: `taskId 202`, IPC 3 мс, разбор 1 мс — модель переиспользована;
- длинный текст: 800 абзацев / 2400 токенов, 169–202 мс, `offsetsOk: true`;
- отмена: `taskId 201` → `cancelled: true`, отмена 1 мс; следующий `taskId 202` запустился и вернул результат за 3 мс;
- память процесса: 342 МБ peak RSS на macOS arm64.

Ошибки:

- модель отсутствует — ошибка с фактическим путём `target/debug/style-models/...`;
- неверный SHA-256 — ошибка до загрузки;
- повреждённый файл (1 КБ) — ошибка SHA-256;
- ошибка парсинга (NUL в тексте) — команда вернула ошибку, редактор остался жив (`editor: true`);
- после ошибки следующий разбор `taskId 302` успешно вернул контракт.

### C.2: resource_dir и теневые состояния

`resource_dir` проверен на настоящем `.app`, собранном через Tauri CLI:

- временный `bundle.resources: ["style-models/*.udpipe"]`;
- модель лежала только в `src-tauri/style-models/` на время сборки;
- запуск без `KABINET_STYLE_MODEL`: модель найдена в `Кабинет.app/Contents/Resources/style-models/...`;
- первый разбор `taskId 101`: IPC 604 мс, разбор 2 мс, 2 предложения, `offsetsOk: true`;
- после удаления файла из `Contents/Resources` ошибка содержит именно этот путь.

Причина прежнего `UnknownPath`: вручную собранный `.app` (без Tauri CLI) не распознавался как bundle; использовать ручную склейку `Contents/MacOS` + `Info.plist` нельзя. Штатный `tauri build` даёт корректный `resource_dir`.

Для будущей поставки потребуется `bundle.resources` с моделью **только после** юридического разрешения. Сейчас ни модель, ни эта конфигурация не коммитятся.

Теневой слой проверен в UI-smoke с отложенными ответами:

- изменение документа сразу инвалидирует выполняющийся запрос (`epoch`), не дожидаясь debounce;
- `disable()` отменяет задачу, увеличивает epoch и очищает состояние; поздний ответ не возвращает его;
- пустой документ даёт явный `status: empty` и не оставляет прежний результат;
- новый запрос сразу выставляет `status: running` и очищает старый успешный результат;
- устаревший ответ не перезаписывает состояние;
- ошибка `style:parse`, недоступная команда и некорректный ответ дают `status: error`;
- ошибка `style:cancel` не блокирует новый разбор;
- поздний ответ после изменения текста/disable не восстанавливает успешное состояние;
- после ошибки следующий запрос восстанавливается;
- ни один из этих сценариев не создаёт подсветку.
