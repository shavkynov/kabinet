# F.3.2 — проверка установленного приложения с реальной Russian-GSD

**Итоговый статус: `ACCEPTED WITH CAVEATS`.**

Полный пользовательский жизненный цикл проверен сочетанием сквозных автоматических тестов (`StyleParser` на реальной `russian-gsd-ud-2.5-191206`, VM-теста реального UI-модуля `29-style-shadow.js` + `analysis.js` + `pm-ranges.js`), а также локальной релизной сборки и изолированного запуска macOS-пакета `Кабинет.app` / `.dmg`. В ходе проверки выявлены и исправлены три краевых дефекта клиентского UI-переключателя в `renderer/app/29-style-shadow.js`. Интерактивный клик-тест в реальном окне установленного NSIS-установщика Windows и в установленном `Кабинет.app` с реальным файловым диалогом ОС требует ручной проверки или отдельного UI-стенда и не выдавался за пройденный E2E.

## 1. Исходное состояние и внесённые исправления

- **Ветка:** `feature/linguistic-style-engine` (база перед началом этапа — `fb43250b6a08ccf30aa4e2927d581d63db4c9bd8`).
- **PR #9** остаётся `Draft`, `main` и PR #8 не изменялись, модель `.udpipe` в Git и установщики не добавлялась.

**Исправленные краевые дефекты в [renderer/app/29-style-shadow.js](file:///Users/rrrr/.gemini/antigravity/scratch/kabinet/renderer/app/29-style-shadow.js):**
1. `styleShadowEnabled()` проверяла `kabinet.styleEngineShadow === '1'` раньше `kabinet.styleEngineMode === 'basic'`, из-за чего при выставленном ранее флаге тени переключение чекбокса в базовый режим не отключало движок после перезагрузки. Теперь приоритет у явного режима `'basic'`.
2. При снятии галочки `#styleEngineToggle` дополнительно очищается `kabinet.styleEngineShadow`.
3. В обработчике `#btnStylePickModel`: статус `«Языковая модель подключена»` показывается только при `st.ready === true`, а в `catch` вызывается `refreshStyleEngineUi()`, чтобы кнопка и текст статуса всегда отражали реальное состояние файла на диске после ошибки установки/замены.

## 5. Непроверенные сценарии и ограничения

1. **Интерактивный клик-сценарий внутри реального WebView2 (Windows) и WKWebView (macOS) в установленном из NSIS/DMG приложении** с реальным системным диалогом выбора файла (`rfd::AsyncFileDialog`) не автоматизирован (на macOS `tauri-driver` не поддерживает WKWebView; на текущей машине нет Windows-хоста).
2. **Установка и запуск NSIS-инсталлятора (`.exe`) на Windows** локально на macOS невозможны; на GitHub Actions проверяются компиляция и сборка (`build.yml` и `tauri-app.yml`), но не установка в пользовательскую сессию Windows с реальной моделью.
3. **Установленная Linux-сборка (`.deb`)** после исправлений F.3.1-C/F.3.2 повторно на Linux-стенде не запускалась (проверяется в CI на уровне тестов и компиляции, а реальный `.deb` требует Linux-стенда с WebKitGTK).
4. **Примечание по результатам CI:** прогоны GitHub Actions (`build.yml` для PR #9 и при наличии доступа `tauri-app.yml`) запускаются после push этого отчёта и отражаются в итоговом сообщении по задаче.
