## Требования и критерии задач

### 1. Межустройственная запись

Проверить write_checked/push и все remote.write, export/replace/keep, yandexdisk.rs/do_write. Есть предварительное чтение, overwrite=true и проверка MD5; это не CAS. Исследовать документированные условные запись/удаление; не выдумывать ETag. Если примитивов нет — безопасный протокол версий/конфликтов, оценка неизменяемых объектов/журнала, совместимости и recovery. Чужое содержимое сохранять и проверять до уничтожения. В keep ошибка чтения имени не разрешает перезапись; ошибка обязательной облачной копии не маскируется успехом. Разделить гарантии локальной/облаччной копий.

2026-11-14, агент (DeepSeek), ИССЛЕДОВАНИЕ официального API ([документация Яндекс Диска](https://yandex.com/dev/disk-api/doc/en/)): изучены `resources/upload` (параметр `overwrite`), объект `Resource` и список поддерживаемых запросов.
- `Resource` содержит `md5`, `modified`, `size`, `custom_properties`, но НЕ содержит `revision`/`etag`/номера версии; эндпоинта истории версий нет (GET `/versions` → 404); условной записи (`If-Match`/precondition) в Disk REST API нет.
- `overwrite=true` по документации = «удалить существующий файл с тем же именем и сохранить загруженный» — это last-writer-wins, не CAS. `overwrite=false` = отменить загрузку, если файл уже есть (create-only; пригоден для захвата/лока).
- `md5`/`modified` — для обнаружения изменений, но не как предусловие записи. Асинхронные copy/move/delete — 202 + опрос статуса. `custom_properties` (meta-add) — строковые пары без атомарности.
Вывод: настоящего CAS в API нет; текущая реализация (чтение + `overwrite=true` + проверка MD5) — LWW, не межустройственная защита.

Предлагаемый безопасный протокол (примитивы только реальные — `overwrite=false`, `md5`, неизменяемые объекты; без выдуманных ETag):
1. **Поколение**: писатель создаёт `gens/<uuid>.json` с `overwrite=false` (create-only). Успех = уникальное поколение; `PlatformResourceAlreadyExists` = перевыбор.
2. **Манифест** `manifest.json` указывает на текущее поколение; обновляется `overwrite=true`, но перед перезаписью чужой манифест сохраняется (`.md5` сверяется) — иначе остановка, а не затирание.
3. **Замок** `lock.json` с токеном устройства и TTL создаётся через `overwrite=false`; снимается только при совпадении токена. Просроченный TTL освобождается, но TTL берётся не меньше максимального времени прохода + запас (без слепого доверия местным часам).
4. **Неизменяемые объекты**: новые версии файлов пишутся как `objects/<sha256>` (create-only, идемпотентно); манифест переключается на новый набор, старые объекты не перезаписываются.
5. **Сбой/offline**: неопубликованное поколение не становится текущим; при расхождении манифестов побеждает более новое поколение, старое и конфликтующие файлы уходят в «Конфликты».
6. **Остаточные риски**: LWW на одном и том же объекте; просроченный замок при падении (TTL); разница часов устройств; рост места под поколения (ротация с проверкой). Это исследование, не реализация; статус № 1 остаётся PARTIAL.
