# Живое ТЗ: сохранность данных и выпуск Кабинета

## Назначение и процесс

Каноническое ТЗ для ветки `main`. Дата актуализации: 2026-11-18, проверенный HEAD: `8ff0b0c`.

Каждый агент до начала работы читает `AGENTS.md` и это ТЗ целиком, проверяет HEAD и рабочее дерево, перепроверяет выбранную задачу в коде. При изменении кода обновлять задачу в том же логическом коммите: статус, SHA проверки, функции, регрессионные тесты, команды и результаты, ограничения и следующий шаг. Документационный коммит не считается исправлением.

**В ТЗ только незакрытые задачи.** Выполненные удалены 2026-11-18 по решению автора; полная история до `8ff0b0c` остаётся в git. Не создавать конкурирующие реестры, новые проблемы добавлять сюда.

Исправления — небольшими блоками с регрессиями, по возможности падающими до исправления. Тесты используют только временные данные. Ошибка не означает отсутствие или пустоту; при неопределённости опасную операцию запрещать. Сеть не должна блокировать локальное письмо. Не заявлять о запуске невыполненных команд.

## Принцип простоты (решение автора)

Кабинет — максимально простой в понимании и использовании, без урезания функционала. Сценарий: один автор, три устройства по очереди (дом ПК → телефон → рабочий ПК), облако — только Яндекс Диск. Защита: папка проекта на устройстве + отдельная папка синхронизации, сохранение сначала локально, потом в облако, взаимная перезапись исключена; поверх — резервные копии (до 30, автор знает, где они). Злоумышленник с доступом к облаку — не главная угроза. Новую защиту добавлять только при строгой необходимости; при выборе между двумя путями — более короткий и понятный. Интерфейс и внешний вид в это ТЗ не входят.

## Действующие решения (закрытые задачи)

- **№ 1, межустройственная запись — закрыто.** Защита: `write_checked` (перечитывание перед записью), create-only для новых файлов, «Конфликты», резервные копии. Протокол поколений/`objects/<sha256>`/манифеста отменён: для трёх личных устройств по очереди он неоправдан и несовместим с телефоном. Остаточное окно LWW (между проверкой и записью) принято; при редкой одновременной записи проигравшая версия уходит в «Конфликты» либо остаётся в резервной копии.
- **№ 3, строгое чтение syncguard; № 4, пустота глав; № 9, статистика; № 14, Rust lock — закрыты.** № 4 заменён явным выбором при первом подключении: `take_cloud`/`takeCloud` (взять облако) или `replaceAll` (выгрузить своё); эвристики `adopt_remote_structure` удалены. Проигравшая сторона сохраняется в «Конфликты».
- **№ 16, упрощение системной логики — закрыто.** Единое решение по файлу (`settle` в JS и Rust), единая `keepCopy`, слияние `projectMeta` по id, отказы вместо подавления ошибок.
- **№ 12, паритет с Electron — закрыто.** Все следы Electron удалены из `main`; Tauri — единственная настольная версия. Сравнивать больше не с чем.
- **Подпись.** Платные сертификаты Windows и Apple Developer ID/нотаризация не приобретаются. macOS — бесплатная ad-hoc подпись, Windows — без подписи; SmartScreen/Gatekeeper документируются, но не обходятся автоматически. Автообновление не требуется.
- **Замок.** Rust не пишет `kabinet.lock` и не блокируется им. Это информационная отметка телефона (Android) «проект открыт на устройстве»; она не входит в синхронизацию и не блокирует проход.

## Требования и состояние задач

### 2. Облачное удаление — PARTIAL

**Требование.** Не удалять при ошибке или неопределённости; сохранить и проверить чужую версию; различать 404, ошибки и незавершённое асинхронное удаление; передавать результат удаления.

**Сделано.** `settle`/`push` не подавляют ошибки чтения и удаления; чужая версия при локальном удалении сохраняется в «Конфликты»; есть тесты на недоступность, ошибку чтения, чужую правку, асинхронное удаление (202 + операция), отсутствующий файл, сбой и повтор.

**Осталось.** Гонка «прочитал → DELETE» между устройствами: атомарного CAS в API нет, протокол № 1 отменён, окно принято. Проверить на реальном Яндекс Диске; отдельно — удаление при массовом исчезновении и повтор после уже выполненной облачной операции.

**Тесты.** `delete_keeps_cloud_file_when_cloud_read_fails`, `delete_reports_cloud_remove_error`, `local_delete_failure_is_reported_not_hidden`, `local_delete_preserves_changed_cloud_version_before_removing`, `async_cloud_delete_is_confirmed_by_operation`, `failed_pass_is_retried_and_succeeds`.

### 5. Облачный снимок — PARTIAL

**Требование.** Пагинация `total`/`offset`, отказ при пустой промежуточной странице; стабильность `total`, дубли/пропуски/перестановки, согласованность каталогов; доказать полноту либо запретить удаления по сомнительному отсутствию; `MASS_DELETE_MIN=5` недостаточен.

**Сделано.** Пагинация и отказ от пустой страницы; перед удалением локального файла выполняется прямое чтение; тесты на ошибку страницы, дубли, 404 посреди обхода, исчезновение всего списка, нестабильный `total`.

**Осталось.** Два одинаковых обхода не доказывают атомарность; маркеры удалений из отменённого протокола № 1 не делать. Нужно проверить на реальном API, что неполный список не приводит к удалению, и решить, достаточно ли прямого чтения. `MASS_DELETE_MIN=5` сохраняется как грубая защита.

**Тесты.** `remote_list_paginates_without_losing_files`, `empty_intermediate_page_is_rejected`, `list_page_error_is_reported`, `disappearing_list_stops_before_deleting_anything`, `folder_gone_from_listing_does_not_delete_local_files`, `duplicate_listing_entry_is_handled_once`, `unstable_total_does_not_delete_local_files`, `incomplete_listing_does_not_delete_local_chapter`.

### 6. Границы проекта — PARTIAL

**Требование.** Не обходить symlink/junction; защитить read/write/delete/mkdir/backup/restore внутри корня; учесть подмену компонентов пути; документировать ограничения.

**Сделано.** `walk_local` использует `symlink_metadata` и не входит в папки-ссылки; `backup` не обходит junction; тесты для junction и обычной вложенности.

**Осталось.** Полный слой проверки путей для read/write/delete/mkdir и backup/restore; файловые symlink на Windows/macOS; абсолютные и подменённые пути state/cache; гонка подмены компонента между проверкой и операцией.

**Тесты.** `walk_local_does_not_enter_linked_folder`, `normal_structure_is_walked_by_folders`, `backup_does_not_follow_directory_junctions`.

### 7. Проверяемые копии — PARTIAL

**Требование.** Fail-closed обход/чтение, хеши содержимого, версионируемый манифест, проверка до публикации, согласованность при изменениях; ротация только после подтверждения новой копии; состав копии и совместимость старых копий.

**Сделано.** `list_files` и `signature` возвращают ошибки; хеш содержимого для всех файлов; `verify_backup`; проверка подписи до `rename`; лимит 30 копий (10 последних + по одной за день + новые); показ пути и открытие папки; тесты на порчу, отсутствие подписи, бинарные изменения при тех же size/mtime, junction, состав.

**Осталось.** Версионируемый манифест и проверка после copy/rename; согласованность при изменении во время копирования; совместимость/безопасный импорт старых копий; ошибки ротации; реальные проекты с >30 копиями; JS-копия не пересчитывает подпись после публикации.

**Тесты.** `backup_detects_binary_change_with_same_size_and_mtime`, `backup_verification_detects_corruption_and_missing_signature`, `backup_skips_own_dir_trash_and_lock`, `retention_keeps_at_most_30_with_recent_and_daily`, `backup_root_is_where_make_backup_writes`.

### 8. Восстановление — PARTIAL

**Требование.** Проверить выбранную копию; предварительно сохранить текущий проект; staging + атомарное переключение либо журналируемый откат; не потерять копии внутри корня; согласовать редактор/watcher/sync; понятный UI, ошибки, безопасный повтор после запуска.

**Сделано.** `restore_backup`: проверка копии, страховочная копия текущего состояния, запись файлов без удаления новых, отказ при повреждённой копии. Меню «Резервные копии → Восстановить из копии…» останавливает обмен, восстанавливает и запускает снова. Журнал отката удалён в № 16.4: страховочная копия остаётся, сообщение называет её.

**Осталось.** Staging/атомарное переключение и восстановление после падения процесса; координация с границей остановки (№ 13); полное восстановление с удалением лишних файлов; выбор копии из списка с датой/размером; тесты нехватки места, copy/rename и прерывания каждого этапа.

**Тесты.** `restore_verified_backup_keeps_newer_files`, `restore_of_missing_backup_is_rejected_without_changes`, `failed_restore_names_the_safety_copy_and_keeps_the_source`.

### 10. State/cache — PARTIAL

**Требование.** Передавать ошибки `mkdir`/записи; успех только после необходимого сохранения; определить авторитетное состояние и безопасный сброс cache; повреждённый `load(state)` не разрешает опасную первую синхронизацию; тесты отказа каждого файла, сбоя между ними, повтора после сбоя и уже выполненной облачной операции.

**Сделано.** `new`/`load`/`save` возвращают ошибки; state — источник истины, cache — производная; отсутствие state = первая синхронизация, порча/неподдерживаемая структура = ошибка; cache фильтруется по state; проверен сценарий «новый state + старый cache».

**Осталось.** Поколения/публикация не вводятся (протокол № 1 отменён). Остаётся проверить отказ каждого файла, повтор после уже выполненной облачной операции, слепое пятно cache по size+mtime, реальный диск/облако.

**Тесты.** `corrupt_state_file_blocks_sync_instead_of_first_sync`, `sync_reports_failed_state_save`, `restart_after_state_saved_but_stale_cache_keeps_both_versions`, `unsupported_state_structure_blocks_sync_without_changes`, `supported_state_structures_load`.

### 11. Durability — PARTIAL

**Требование.** Синхронизация родительского каталога после rename без ухудшения атомарности; определить ошибку после rename; учесть пределы Windows/macOS; тесты записи и сбоев до/при/после rename, аварии где воспроизводимо.

**Сделано.** `write_atomic_bytes` после rename вызывает `sync_parent_dir`: Unix — fsync каталога, Windows — `FlushFileBuffers` с `FILE_FLAG_BACKUP_SEMANTICS` (best-effort).

**Осталось.** Аварийное выключение/перезапуск не воспроизводимы; на части Windows/ФС синхронизация каталога не поддерживается — ошибка игнорируется; macOS-специфика не проверена; политика ошибки после rename не описана в коде для пользователя.

### 13. Остановка sync — PARTIAL

**Требование.** Ограниченная корректная отмена без блокировки локального сохранения и без обязательного сетевого прохода на выходе; сохранять незавершённое; исключить параллельные проходы и работу старого проекта после переключения; тесты stop во время запроса, медленный/недоступный сервер, offline-close, многократные переключения, reconnect/resume, реальное закрытие окна.

**Сделано.** Один флаг `stop` для фонового и ручного прохода, кооперативная отмена на границах операций; `PassOutcome` (done/skipped/stopped/error); `stop` возвращает исход и ждёт не дольше 5 с; один слот прохода на проект (`pass_slots`), старый отцепленный проход держит слот; поздние события фильтруются по проекту; F5 различает остановку и отложение.

**Осталось.** GUI-проверка закрытия окна и многократных переключений; реальные HTTP-таймауты/повторы (ожидание не равно одному таймауту); уже отправленный запрос не отзывается — это осознанное ограничение.

**Тесты.** `s1_1_stopped_pass_makes_no_writes_after_stop`, `s1_2_restart_after_unfinished_stop_waits_for_boundary_and_works`, `s1_3_manual_sync_now_after_stop_reports_stopped_without_writes`, `stop_gives_up_on_a_stuck_thread_within_bound`, `stop_does_not_force_network_pass_and_keeps_change_for_resume`.

### 15. CI и выпуск — PARTIAL

**Требование.** Установщики Windows и macOS, версионированные Releases, артефакты/логи, полный JS/Rust CI, корректные permissions; проверять прогоны workflow, а не только YAML; чистая установка на Windows/macOS без dev tools: установка, первый запуск, OAuth/deep-link, старый проект, понятные предупреждения.

**Сделано.** `bundle.active=true`, установщики собираются в GitHub Actions; релизы 0.39.0–0.40.5 выпущены. 0.40.5: тег `0.40.5`, прогон `44376614751` — все job success, Release с NSIS x64, dmg arm64/intel, Linux AppImage/deb и APK; патчноут собран из `CHANGELOG.txt` с блоком о первом запуске. macOS `.app` в dmg подписан ad-hoc, `codesign --verify --deep --strict` проходит (`Signature=adhoc`, hardened runtime). CI проверяет Rust на Linux/Windows/macOS, JS и `ui-smoke`; релизный workflow по тегу.

**Осталось.** Чистая установка и первый запуск на Windows/macOS; проверка инструкции для SmartScreen/Gatekeeper на реальных машинах; deep-link/OAuth из установленного приложения; старый проект после обновления.

**Не делать.** Платные сертификаты, нотаризацию, автообновление; локальную сборку установщиков (только GitHub Actions).

Проверять затронутые платформы и сборку; не заявлять о выполненных командах, если они не запускались. Установщики — только в CI, локально не собирать.
