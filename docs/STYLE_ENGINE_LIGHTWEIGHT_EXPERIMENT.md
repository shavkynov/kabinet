# Эксперимент: лёгкие правила для цепочек и придаточных

Дата: 2026-11-19. Ветка: `feature/linguistic-style-engine`, база `f95175b`. Экспериментальные правила **не подключены** к UI и не включены по умолчанию. Rust/UDPipe не изменялся и не удалялся.

## 1. Исходная точка

`src/morph.js` возвращает только часть речи (`verb`, `noun`, `adj`, `adv`, `part`, `pron`, `func`, `num`, `other`). Падежа, числа, рода, леммы и зависимостей в его выходе нет. `analyzeBlock()` добавляет границы слов/предложений и пассив, но не дерево.

Следствия:

- нельзя называть эвристику по окончаниям падежным анализом;
- `GEN_LIKE` — только формальное совпадение окончания;
- `morph` ошибается: «требований» → `adj`, «переполненном» → `noun`.

Старые `findChains()` и `findWhichAvalanche()` — regex-правила:

- `findChains`: VN-суффиксы + GEN-окончания, только пробелы, старт с VN, ≥3 слова, ≥2 VN.
- `findWhichAvalanche`: `который`/`, что`, ≥3 маркера в предложении, без дерева.

## 3. Правила A1/A2

### A1 — строгий позиционный run

- именные головы: `noun` или суффиксальная номинализация (с оговоркой, что падеж не определяется);
- между головами: только пробелы и `adj`/`part`;
- местоимения, числительные, предлоги, союзы, наречия, пунктуация разрывают;
- ≥3 головы, ≥2 кандидата в номинализации;
- все непервые головы имеют `GEN_LIKE`;
- лексикализованные стоп-стемы (`здан`, `мнен`, `компан`, …) не дают засчитать хвост;
- confidence: `medium` при ≥3 номинализациях, иначе `low` (предварительно).

### A2 — предложная мягкая цепочка

Отличается не только разрешением предлогов:

- разрешены предлоги;
- разрешён один `adv` перед прилагательным;
- ≥4 именные головы, ≥1 номинализация, ≥2 `GEN_LIKE`/предложных непервых голов;
- обязателен предлог в run;
- confidence `low`.

A2 пытается поймать «Вопрос о необходимости проведения проверки», но на контрольной главе дала FP.

## 4. Правила B1/B2

### B1 — marker heuristic

- `который` в формах;
- `, что` только как союз/местоимение;
- `что-то`, `что ли`, `что бы` (без `ни`) не считаются;
- **учитываются** `потому что`, `так что`, `несмотря на то что`, `при том что`, `что бы ни` как возможные клаузальные маркеры;
- ≥3 маркера в предложении;
- речь героев/цитаты исключаются;
- результат называется эвристикой перегруженности, не подсчётом клауз.

### B2 — punctuation/segment heuristic

- делит предложение по `, ; :`;
- считает **различные** пунктуационные сегменты с маркером и глаголом (не число маркеров);
- требует ≥3 различных сегмента;
- маркер «, что» относится к следующему сегменту;
- три маркера в одном сегменте не дают срабатывания;
- ниже recall, потенциально выше precision.

Ambiguous holdout (3 примера): old 0 срабатываний, B1 3/3, B2 2/3. Это случаи, где маркеры есть, но перегруженность не доказана; B1/B2 их не различают надёжно.

### Overlap-span

Для каждого варианта посчитаны exact-span и overlap-span (пересечение диапазонов; one-to-one). На этом probe значения совпали: ожидаемые фразы и находки имеют одинаковые границы. Это не делает overlap независимой метрикой качества; overlap нужен для диагностики границ, exact остаётся основной.

## 6. Ручная оценка

- Контрольная глава: старые 0/0, A1 0, B1 0, B2 0; A2 1 — ложное/сомнительное.
- A1 на probe не дала FP, но не поймала предложные цепочки и часть положительных.
- A2 дала FP на контрольной главе и низкий recall; как самостоятельное правило не готова.
- B1/B2 убрали известные FP `что-то`/`что ли`, поймали составные союзы; B1 дал 100% на крошечном probe, B2 — 67% recall. Это не доказательство качества; вероятна переобученность под примеры.
- Все confidence (`low`/`medium`) — **предварительные**, не откалиброванные вероятности.

## 7. Стоимость Rust/UDPipe

Измерено временным Rust-бенчмарком `StyleParser` на GSD (не Tauri IPC):

- модель: 14 034 257 байт;
- холодный запуск + разбор 303 абзацев: **1444 мс**;
- повторный разбор: **935 мс**;
- peak RSS: **252 МБ**;
- после `drop(parser)` RSS: **246,7 МБ**, то есть память не возвращается ОС сразу; в приложении сервис вообще живёт постоянно;
- Tauri app ранее: 342 МБ peak, холодный IPC ~0,6–1 с.

Процедура RSS:

1. Запустить отдельный процесс без модели; зафиксировать `ps -o rss= -p <pid>` (в сохранённом прогоне начальное значение не записано — это ограничение).
2. Загрузить GSD и выполнить разбор 303 абзацев; снять `ps` и `/usr/bin/time -l` peak.
3. Повторить разбор с уже загруженной моделью.
4. Вызвать `drop(parser)`, снять `ps` сразу и через 6 секунд.

Команда:

```bash
cd /private/tmp/style-cost
cargo build --release --quiet
/usr/bin/time -l ./target/release/style-cost /private/tmp/russian-gsd-ud-2.5-191206.udpipe
```

Окружение: macOS arm64, Rust stable, release; временный crate зависит от `kabinet-core`; модель GSD 2.5, 14 034 257 байт. В приложении модель не выгружается, пока живёт `StyleParser`.

Это не доказывает необходимость парсера, но и не позволяет заменить его только по цене: A/B покрывают лишь 2 из 8 категорий.

## 8. Точечное исправление «в ужасном месте»

В `src/style.js` `ужас\p{L}*` заменено на формы существительного `ужас(?:а|у|е|ом)?`.

До:

- `Он был в ужасном месте.` → `в ужасном` (FP)
- `В ужасном месте было тихо.` → `В ужасном` (FP)

После:

- `Он был в ужасе.` → `в ужасе` (TP)
- `Он был в ужасном месте.` → []
- `В ужасном месте было тихо.` → []

Добавлены тесты в `test/style.test.js`.
